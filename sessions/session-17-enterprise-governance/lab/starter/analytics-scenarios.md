# Measurement Scenarios

Use the sample data only for this fictional exercise. Before interpreting live information, check the meter, analytics fields, and data-handling rules against current GitHub documentation and customer policy.

## Scenario A: Trial outcome

Compare a bounded trial with a human-reviewed baseline:

1. Which acceptance criteria were met?
2. What rework or review effort was required?
3. What quality and safety observations should be retained?
4. What uncertainty remains?
5. Should the customer continue, pause, or gather more evidence?

## Scenario B: Workflow selection

Use the data to choose a training workflow:

1. Which work is bounded and non-sensitive?
2. Which participants need additional training or review support?
3. Which observations require an administrator or data owner to interpret?
4. Which repository-sandbox exercise would produce the same evidence?

## Scenario C: Metered-work guardrail

For this fictional trial:

1. Identify the customer-defined meter and observation window.
2. Record the threshold, alert, owner, escalation contact, and stop condition.
3. State the manual fallback when the guard is reached.
4. Recommend a next step without estimating commercial terms from the training data.

## Scenario D: Change review

Review the sample events and record the decision:

1. Which changes need an accountable owner to review?
2. Which observations need further investigation?
3. Which claims require current documentation or customer-policy confirmation?
4. What should the team do while that confirmation is pending?
