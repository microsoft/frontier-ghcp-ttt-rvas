# Capstone Checkpoints

Use this list during the lab. Put the evidence in `capstone-handoff.md`.

## Govern

- [ ] Repository or sandbox boundary is named.
- [ ] Synthetic-data rule is recorded.
- [ ] Allowed tools and dependency rule are recorded.
- [ ] Meter, threshold, owner, and stop condition are recorded.
- [ ] Reviewer and fallback are named.

## Specify

- [ ] Each accepted behavior has a specification ID.
- [ ] Acceptance scenarios are observable and testable.
- [ ] Non-goals are explicit.
- [ ] The issue maps each criterion to a specification ID and test.

## Implement

- [ ] Expected files were named before editing.
- [ ] The patch changes only the Bookmark creation slice.
- [ ] No package or unrelated endpoint was added.
- [ ] Blocked work has a file-level patch plan.

## Verify and review

- [ ] `npm test` ran, or the blocked command is recorded.
- [ ] Each acceptance criterion has evidence.
- [ ] A human recorded approve, request changes, or pause.
- [ ] Deferred scope, risk, and the next action have owners.
