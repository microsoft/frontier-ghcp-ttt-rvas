# Session 20: Understand Technical Work Without Reading Code

**Module:** Product and Delivery Teams

**Difficulty:** Beginner

**Prerequisites:** Working access to GitHub Copilot Chat  
**Duration:** 3 hours (1 hour trainer content + 2 hours lab)

## Overview

Product and delivery teams often need to judge technical work before an engineer can explain it. This session teaches learners to use GitHub Copilot to question repository, issue, pull request, and check evidence in business language. Learners separate generated summaries from verified facts, identify product impact and risk, and know when to escalate.

The shared scenario is a fictional, industry-neutral **Service Request Portal**. All names, records, and identifiers are synthetic.

## Learning outcomes

By the end of this session, learners can:

1. Ask focused questions about technical work without reading source code.
2. Connect issue and pull request evidence to user impact, delivery scope, and operational risk.
3. Mark claims as verified, inferred, generated, or unknown.
4. Escalate decisions that need engineering, security, privacy, accessibility, or release-owner review.
5. Produce a one-page product impact and risk brief.

## Access and safety

- **GitHub Copilot Chat is required.** Before the session, confirm that you can sign in, open Chat, submit a prompt, and receive a response.
- The synthetic starter files are the lab evidence. Learners must use GitHub Copilot to analyze and question them.
- If Copilot access fails, stop. Resolve the account, license, policy, or service issue before starting the session.
- Use only synthetic or approved, sanitized artifacts. Do not paste customer data, credentials, private source code, or source organization names into an unapproved tool.
- Generated text is a draft. Confirm material claims against the supplied evidence or an accountable human owner.
