# Session m7-04: Build and use a planning canvas

**Module:** Product and Delivery Teams

**Difficulty:** Intermediate

**Prerequisites:** Sessions m7-01 to m7-03, GitHub Copilot app access, GitHub MCP access, and canvas creation access

**Duration:** 3 hours (1 hour trainer content + 2 hours lab)

## Overview

Continue the **Delivery Decision Studio** path. Use the built-in
`/create-canvas` skill to turn the live Session m7-03 issues into a visible delivery
workspace. Review the generated extension and remove capabilities you do not need.
Then change GitHub state and compare it with the canvas. Detect the stale data
and refresh it.

You describe and operate the canvas without hand-coding the extension.

The GitHub MCP connection supplies issue tools. A plugin may package MCP and
canvas capabilities, but it does not replace connection or capability review.
Keep the lab no-code and free of customer or source organization names.

> [!IMPORTANT]
> **Live canvas creation is required.** Stop if `/create-canvas`, GitHub MCP, or the approved canvas actions are unavailable.

## Learning outcomes

In this session, you will:

1. Decide when a canvas is more useful than another chat response.
2. Describe the state and actions needed for a planning canvas.
3. Create a canvas from a plain-language request.
4. Review and simplify the generated capabilities.
5. Load approved GitHub issues into the canvas.
6. Detect drift between visible canvas state and a fresh GitHub read.
7. Refresh and reconcile the canvas.
8. Record ownership, refresh, recovery, and retirement conditions.
9. Leave a live canvas linked to the GitHub issues for Session m7-05.
