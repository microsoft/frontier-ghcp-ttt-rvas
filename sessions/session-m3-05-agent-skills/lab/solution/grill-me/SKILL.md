# Grill me

Interview the user until the plan is clear enough to build. Don't write code or a plan until the interview is done.

## How to interview

1. Read any file the user points to. Never ask what the file already answers.
2. Ask **one question at a time**. Wait for the answer.
3. For each question, give your recommended answer so the user can reply "yes" or correct you.
4. Follow the answer. If it opens a new gap, go there before moving on.
5. Cover these areas, skipping what's already settled: goal and audience, scope and non-goals, owner, data and inputs, failure cases, how to tell it worked.
6. Push back once on vague answers ("soon", "everyone", "somehow"). Ask for a concrete example.

## When to stop

Stop when you could hand the plan to a colleague and they would not need to ask you anything. Then write a summary with:

- **Decisions** made, one line each
- **Open questions** that remain, with an owner if known
- **Next step**

Ask the user to correct the summary before you finish.
